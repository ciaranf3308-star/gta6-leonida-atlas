VICEWIRE · INDEPENDENT COMMUNITY PROJECT

About the ViceWire

An independent atlas that makes GTA VI location evidence legible, explorable and honest about its limits.

Current release: v0.30.1

Why this exists

Public trailers, screenshots, official pages and community research reveal fragments of Leonida. The atlas gives those fragments a shared frame so readers can inspect relationships without mistaking an estimate for confirmed geography.

This is a community project, not an official map, a leaked game asset or a promise that every road and landmark will appear in the released game.

What approximate means

Community-derived coastlines, routes and positions can change when better evidence arrives. Uncertainty stays visible; unsupported areas remain unknown instead of being completed by guesswork.

Your own atlas

Explore the bundled map as a guest, keep favorites and notes, organize collections and add personal markers. Your edits live in this browser’s IndexedDB storage. Export a backup to keep a portable copy or move your work between browsers.

Personal annotations are separate from the source catalogue. They never turn a community estimate into a confirmed location.

Independent by design

The public application builds as static files and runs without a CMS, private server or account. Its source code is licensed under AGPL-3.0-only. The optional 3D explorer uses the same community coordinate frame.

Where ViceWire is used

  • GitHub Pages hosts this build, deployed from the VICEWIRE repository (spoiler-free-pwa branch).
  • GTA6State and Zonepedia host the upstream Leonida Atlas — not this fork.

    Independent QA's verdict on v0.30.0 was SHIP, with four findings. v0.30.1 fixes exactly those four — a legacy AI record that aborted the whole migration, a PWA update that took two opens, an offline reload that failed after exactly one visit, and onboarding counts jammed against their layer names.   2. v0.30.02026-11-25

    Reproducible from a clean checkout — content-hash versioning, honest docs, CI on the branch

    The stabilisation audit's reproducibility lane: the app was not reproducibly buildable from a clean checkout (tile generation was tribal knowledge), the tile-cache fingerprint hashed filenames + sizes instead of content, and the README still described upstream Leonida Atlas. v0.30 fixes all three — one script from clone to verified build, a content-hash fingerprint, and docs that say VICEWIRE, not upstream.

  3. v0.29.02026-11-25

    Make it snappy — tile prefetch, a bigger tile cache, and a faster layer toggle

    The user's verdict on v0.28's look was 'Yeah looks wise with the map I'm happy now' — and then 'Just performance is POXY.. no way we can preload all the layers so it's snappy as hell?' v0.29 is the performance lane, profiled first: cold load settled tiles in ~1.6s, a full zoom-in fired ~190 tile requests, and a two-minute drive loaded ~620 distinct tiles — past a third of the old 1,500-entry service-worker cap, which evicted the oldest tile on every put past it. It warms the working set on idle instead of preloading all 31,527 tiles (~197 MB) up front, which would thrash his phone.

No generative AI anywhere. Building footprints stay visible because the grade never paints over them.
